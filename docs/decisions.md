# Decisions

One line per decision: what, and why.

- Git `user.name` was unset globally; set repo-local identity to the GitHub account name "Simarpreet Singh" with the global email. Why: PRD requires owner identity only; no global changes allowed.
- Claude Code attribution disabled in `.claude/settings.json` (`includeCoAuthoredBy: false`, empty `attribution`). Why: PRD authorship rule.
- TypeScript pinned to ~6.0 instead of 7.0. Why: typescript-eslint supports `<6.1`.
- Playwright project uses WebKit with the `iPhone 15` device profile. Why: PRD requires WebKit iPhone emulation.
- Playwright WebKit browser installed into the user's existing Playwright cache (AppData\Local\ms-playwright), which already held Chromium. Why: needed for E2E; user-level, removable.
- XP curve changed to `285 × L^0.84` (docs/game-design.md §4.1). Why: PRD curve reaches level 50 in ~3.5 years, missing its own 1-year target (R2).
- Class prescriptions split by experience level with R5 corrections (beginner lane, Ranger loads, longer compound rest). Why: R5 §0.
- Barcode scanning uses the `barcode-detector` ponyfill over self-hosted `zxing-wasm` instead of `@zxing/browser`. Why: R7 §8 — Safari lacks BarcodeDetector; the ponyfill is maintained and the wasm is ~1 MB.
- No Cloudflare Access; unlisted URL + app PIN + bearer-token Worker. Why: R7 §9 — Access breaks cookie-less manifest/icon fetches in standalone mode (PRD fallback).
- Push from the Worker with `@block65/webcrypto-web-push`; VAPID subject must be an `https:` URL. Why: R7 §1, §10.
- Service worker uses Workbox injectManifest. Why: custom push handler + range requests (R7 §2).
- Exercise library = hasaneyldrm (GIFs, private build) ∪ free-exercise-db (Unlicense). Why: most exercises with animation + public-domain backbone (R4, R6).
- Body map from MuscleMap (MIT) male/female path data. Why: only MIT source with both sexes, front/back, delt heads (R6).
- Cuisines: India, USA, UK, Mexico, Italy, China, Japan, Thailand, Lebanon/Middle East, Greece/Mediterranean, Korea, Brazil, Spain, France, Pakistan + generic. Why: R6 §3 (owner is Indian; Pakistan shares dish vocabulary).
- Audio: original sounds synthesised in Node at build time to WAV, played with Howler. Why: PRD names Howler; synthesis keeps all sound assets original.
- Exercise media committed as converted animated WebP under public/assets/third-party/, runtime-cached (not precached). Why: deterministic offline-capable build without network at deploy time; precaching ~50 MB on install is hostile on iOS.
- Red Gate minimum rank C (canon B). Why: B rank arrives ~day 195; the challenge should be reachable earlier.
- Fonts self-hosted via Fontsource (Orbitron display, Rajdhani UI, Inter body, JetBrains Mono numbers). Why: works offline; matches fan consensus (R1 §12.2).
- `--shadow-purple` (#7B2FF7, 3.4:1) limited to borders/fills/large text; `--shadow-purple-text` (#A77BFF) for text. Why: WCAG AA.
- Shadow art is procedural SVG per archetype with seeded variants instead of hand-painted art. Why: original, tiny, infinitely many unique shadows.
- Visual snapshots taken with reduced motion and a fixed clock. Why: deterministic screenshots.
- CI runs Playwright with `--ignore-snapshots`; visual regression is checked locally on the owner's Windows machine where snapshots were approved. Why: font rasterisation differs on Linux runners.
- Exercise library: 1,915 exercises = hasaneyldrm (spine, GIFs) ∪ free-exercise-db (unmatched entries kept with 2-frame media); match at token-Jaccard ≥ 0.8 with the same first equipment and a shared muscle. Why: R6 merge strategy; 0.75 produced wrong merges (bench press ↔ bench press with chains).
- Exercises that appear in both datasets, or match a hand list of common lifts, are tagged `core` (259) and preferred by the plan generator. Why: popularity proxy without manual curation of 400 lifts.
- Tips/mistakes authored per movement pattern (18 patterns) plus dataset "Tip:" sentences. Why: no dataset has mistakes; pattern-level coaching is accurate and covers all 1,915.
- Only English instructions kept. Why: the owner reads English; cuts bundle size.
- Ingredient table: 305 curated rows resolved by query against the frozen SR Legacy release + IFCT codes; 755 dishes across 16 cuisines authored as raw-gram recipes with macros computed at build time. Why: R6 §2.4, §3.3.
- Dish authoring was split across four subagents writing data/dishes/*.json against the real ingredient ids, validated by `data/build-dishes.ts`.
- Exercise media are committed (58 MB WebP). Why: offline-capable deterministic builds; private repo.
- Gallery visual snapshot spec skips on CI (Linux WebKit crashes on the heavy gallery page, #94); snapshots are verified locally. Why: unblock CI for functional E2E.
- CI runs on windows-latest (2× minutes, still free quota; full CI only on demand). Why: Linux WebKit crashes/never settles on our SVG-heavy pages (#94) while Windows WebKit matches local runs and the approved snapshots; the product target is iOS Safari, not Linux WebKit.
- Form analyser is validated against synthetic "recorded" clips: a kinematic stick-figure driven through known reps with MediaPipe-style landmarks, noise, low frame rate, tempo jitter and injected faults (tests/fixtures/form/synth.ts). Why: no licensed video clips exist in the repo and MediaPipe cannot run headless in Node; real-iPhone clip validation is listed as an owner task.
- Counting thresholds are lenient (partial reps still count) while rules hold strict depth/lockout standards. Why: a shallow rep should be counted and corrected, not ignored.
- Form check uses the front camera, mirrored, MediaPipe lite model with GPU delegate and CPU fallback; model and wasm self-hosted (~32 MB, runtime-cached). Why: R7 §7.
- Push Worker keeps one KV record per device (`dev:{id}`: subscription, IANA timezone, schedule, today's booleans, sent markers). Reminder times are local; the Worker converts with `Intl` so travel and DST need no client work. Why: one read per device per cron run, ~30 writes/day (R7 §9).
- A reminder fires up to 30 minutes after its time, once per local day, and failed sends (429/5xx) retry on the next run; 404/410/VapidPkHashMismatch delete the device. Why: cron is every 15 min and may skip a run.
- Bearer token for the Worker is shipped in the app bundle (VITE_PUSH_TOKEN). Why: single-owner app on an unlisted URL; the token only lets someone set reminder times. It stops casual abuse, not a determined attacker; rotate with `wrangler secret put API_TOKEN` if leaked.
- Client sends daily status from a Dexie `liveQuery` over today's data, debounced 2 s and only when a value changes. Why: one place catches every log path (sets, water, meals, check-ins) without hooking each one.
- Push runs in mock mode when VITE_PUSH_* is unset: the toggle and schedule work, nothing leaves the device. Why: keeps the app and tests working before the owner deploys the Worker.
- `calorie_check` push text uses a fixed line because every catalogue variant needs kcal numbers, which never leave the device.
- The Worker uses minimal local types for KV/handlers instead of `@cloudflare/workers-types`. Why: no extra dependency for four methods.
- App PIN is per device: the PBKDF2 hash lives in settings (and in backups), and a localStorage flag lets the Shell decide synchronously at launch whether to show the lock. Why: an async "pending" render at startup coincided with live queries missing updates in WebKit (#115); a restored backup on a new device asks for a new PIN to be set.
- Backups contain every store except the bundled exercise library (rebuilt from the app); photo bytes travel as base64 `{ $ab }`; restore is one all-or-nothing transaction and refuses files from a newer DB version. iOS gets the share sheet first ("Save to Files"), then an anchor download (R7 §11).
- Imported Hevy/Strong history becomes normal workouts and sets (it feeds e1RM, PRs, recovery and the report) but awards no XP or gold. Why: XP is earned in the System; importing years of history would skip the whole level curve.
- Import matching: exact name/alias, then a small curated table for generic names ("Squat (Barbell)" → Barbell Full Squat), then token overlap with gear-word penalties as suggestions the Player confirms. Distance-only rows become cardio logs.
- Backup reminder runs 5 s after launch at most once per 7 days, as a System message.
- Cold-load performance: inline boot splash in index.html, exercise library seeded when idle, every non-Status route lazy. Lighthouse mobile (simulated): performance 64-68, accessibility 100, best practices 100. preact/compat was tried and reverted (main chunk 146 → 99 KB gzipped but no score change and higher blocking time). The remaining gap is render time under 4x CPU throttling; tracked in #120. Installed apps launch from the service worker cache.
- Cloudflare Pages config lives in `public/_redirects` and `public/_headers`; HTML, manifest and service worker are `no-cache` so installed apps see updates; the site sends `noindex`.
- Startup jobs are self-healing: ensureToday re-syncs today's nutrition progress (#116), the Titles screen re-checks earned titles, and refreshPlayer writes inside a transaction so it never clobbers concurrent changes (#126).
- Design v2 (research/design-v2.md): one hero window per screen with the full System frame; everything else quiet cards, sections and inset groups; Orbitron limited to numerals and moments. Why: every panel had identical chrome, so nothing read as important.
- Glitch effects: materialise on window entry, tap glitch on primary actions/nav/rows, tear band on route change; all CSS transform/opacity/clip-path, reduced-motion fallbacks; never on steppers or set logging. The first screen after launch renders without entrance effects (LCP).
- No backdrop-filter/filter on panels; glass is a translucent fill over one fixed ambient light layer. Why: invisible over a flat background but expensive (and a WebKit filter bug), measured in Lighthouse render delay.
- Startup: Shell, Status and Awakening are lazy; the Awakening has a 3.5 kB entry gate (install guide / offer) and the onboarding flow loads behind it; a localStorage hint routes a new device straight to the gate, and the gate re-checks the database before Accept. Fonts are Latin-only (6 faces). Howler loads on first tap. Result (Lighthouse 12.8.2, simulated mobile, median of 5): `/` 90, `/awakening` 93, accessibility 100, best practices 100.
- The exercise library seeds in a Web Worker, keyed on the hashed asset URL (parsed only when the file changes) and single-flight. Why: parsing 2.9 MB on the main thread blocked taps and, with fast onboarding, made the Awakening save wait 30 s+.
- Sounds: Kenney (CC0) for UI, Mixkit Free License for stings and cinematic sounds (research/sfx.md); arise and boss are layered; all about -16 LUFS; WAV 44.1 kHz, mono for UI, stereo for stings; ambient loop at 22 kHz. Picked from measurements, not by ear: the owner auditions them (needs-owner §5).
